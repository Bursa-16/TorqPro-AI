# TorqPro AI v3.1.0 — Release Notes

**Status:** Stable, 2026-08-29.
**Baseline:** `v3.1.0-alpha.1` (`da1833c4cf3897603ebd897b1cb542d64c1c532c`).
**HEAD:** `e395635299e0f6b92409f94d912433986f13cfec`.
**Previous stable release:** `v3.0.0` (`50f1a0f9632982b6c90dda494df4f86d9eca61ab`, 2026-08-13).

v3.1.0 adds a governed AI gateway with real provider implementations,
a Question Bank AI frontend, and a full six-phase UX polish cycle
covering accessibility, responsive design, navigation IA, and state
improvements. Deterministic engineering calculations remain the sole
authoritative source for all numeric engineering results and were not
modified in this release.

---

## AI / Knowledge Gateway (AI-B1–B5, AI-P1, AI-P1A, AI-P2L, AI-P2L-R, AI-F1)

### Governed AI Gateway (AI-B1–B5)

- `AI_SCHEMA_VERSION = "1.0"` applied to all AI endpoint responses.
- `validate_model_response()` validates every model output before
  delivery; invalid output → HTTP 503 (`ModelOutputValidationError`),
  never silently forwarded.
- `POST /api/ai/question-bank/search` — provider-independent,
  publishable-only semantic Question Bank search.
- `POST /api/ai/question-bank/explain` — exact approved-record AI
  explanation; `publishable_only=True` is enforced server-side, not
  a client parameter.
- `ModelTimeoutError` / `ModelUnavailableError` contract with explicit
  `timeout_seconds` parameter on all `complete()` signatures.
- Persistent hash-only audit trail (`ai_audit_records`) reused for
  QB Explain; raw prompt/response text is never stored.

### Anthropic Provider (AI-P1, AI-P1A)

- `AnthropicModelClient` via `httpx` (no SDK dependency).
- Default model: `claude-sonnet-5`; default `max_tokens: 16000`.
- Configured via `TORQPRO_ANTHROPIC_ENABLED` / `TORQPRO_ANTHROPIC_API_KEY`.
- Disabled by default. The Anthropic path has an external API fee;
  operators must explicitly enable it.

### Ollama Local Provider (AI-P2L, AI-P2L-R)

- `OllamaModelClient` via `httpx`; targets the Ollama Chat API
  (`/api/chat`, `stream: false`).
- Configured via `TORQPRO_OLLAMA_ENABLED` / `TORQPRO_OLLAMA_BASE_URL`
  / `TORQPRO_OLLAMA_MODEL` / `TORQPRO_OLLAMA_TIMEOUT_SECONDS`.
- `keep_alive` (AI-P2L-R): configurable via `TORQPRO_OLLAMA_KEEP_ALIVE`
  (default `"10m"`); controls how long the model stays loaded in VRAM
  after a request.
- `OllamaReadinessStatus` enum + `check_readiness()`: lightweight
  `GET /api/tags` probe distinguishes `SERVER_UNAVAILABLE`,
  `SERVER_REACHABLE`, `MODEL_MISSING`, `MODEL_READY`. Never called
  automatically at startup (avoids blocking application start).
- Recommended first model: `qwen3:8b` (default). One target machine
  was validated with `qwen2.5:3b`; this is not a universal product
  default and is overridable via `TORQPRO_OLLAMA_MODEL`.
- Local Ollama inference has **zero external API fee**. Hardware
  performance and memory availability are the operator's
  responsibility.
- **PAID_CLOUD_AUTO_FALLBACK = NO**: Ollama failure never silently
  routes to the Anthropic adapter. The two providers are independent
  registry entries.
- **MODEL_AUTO_DOWNLOAD = NO**: TorqPro never calls `ollama pull`.
  Missing models are reported via `OllamaReadinessStatus.MODEL_MISSING`.
- **MODEL_AUTO_SUBSTITUTION = NO**: a missing or failing model is not
  silently replaced with an alternative.

### Question Bank AI Frontend (AI-F1)

- "AI Search" and "Explain with AI" surfaces on the existing QB screen.
- Approved QB content always rendered **above** and visually stronger
  than the AI explanation.
- AI explanation rendered via `textContent` (no raw AI HTML executed).
- `source_id` never interpolated into JS `onclick` string context
  (`data-qid` attribute pattern).
- Provider, model, API URL, and API key never exposed in the UI.
- Evidence anchor and disclosure always visible.
- AI error states do not disrupt the deterministic QB result.

## Deterministic Engineering

All deterministic engineering engines (`vdi2230_core`,
`calculation_engine`, `torque_recommendation`, `engineering_core`,
`spc`, `production_validation`, `library`, `governance`) are
**unchanged** in v3.1.0. Deterministic calculations remain the sole
authoritative source for numeric engineering results. No AI component
can modify, override, or recompute a deterministic value; this is
enforced structurally (AST-based dependency guard) and by test.

---

## Document Intelligence

Secure document ingestion (Magika content-type detection, OOXML
structural guards, MarkItDown adapter, SQLite ingestion service,
Tesseract OCR fallback) is preserved from v3.0.0. No Document
Intelligence capability was added or removed in v3.1.0.

## UX / Frontend (UX-P1 through UX-P4B)

### Navigation Information Architecture (UX-P1)

- Primary navigation reduced from 29 visible items to 25 items across
  5 semantic groups: Overview, Engineering, Quality & Production,
  Knowledge, Project & Traceability.
- Stub/unfinished pages (`fmea`, `projects`, `revisions`, `approvals`)
  removed from primary navigation; all 46 `page-*` DOM IDs preserved.
- Removed pages carry truthful "under development" banners.
- All sidebar navigation items converted from `<div>` to `<button>`
  (keyboard Enter/Space activation).

### Accessibility (UX-P2A, UX-P2B, UX-P2C)

- Native `alert()` replaced with `tpAlert()` — `role="alertdialog"`,
  `aria-modal`, Escape/OK handling, focus management, HTML-escaped
  messages, EN/TR i18n.
- Global `:focus-visible` CSS for all interactive controls.
- `@media (prefers-reduced-motion: reduce)` disables non-essential
  transitions and animations.
- Shared `trapFocus()` / `releaseFocus()` helpers for Tab cycle and
  focus restoration; wired to modal open/close.
- 210 `<th scope="col">` attributes on table column headers.
- Checklist ✓/✗/— buttons and mobile 📱 button received `aria-label`
  values (EN/TR i18n keys).
- **235/235 real rendered form controls** now have a valid accessible
  name (`label[for]`, `aria-labelledby`, or `aria-label`).
- Positive `tabindex`: 0.

### Responsive / Mobile (UX-P3)

- `div.table-responsive` scroll wrapper added to 12 static tables;
  native `<table>` keeps `display:table` (ARIA table role preserved).
- Form grids collapse to 2 columns at 768 px and 1 column at 430 px.
- `max-width:100%; box-sizing:border-box` applied to all form controls.
- Modal width constrained to `min(92vw, 520px)` at all viewport widths.
- Long engineering strings use `overflow-wrap:anywhere`.
- 375 px compact table font and topbar button treatment.
- RESPONSIVE_IMPLEMENTATION = STATICALLY_VALIDATED (no real-device
  browser rendering was performed).

### State Improvements (UX-P4, UX-P4B)

- Dashboard getting-started card with 5 shortcut actions.
- Dashboard demo/sample data clearly labeled (banner + section note).
- Explicit initial/empty state messages added to: Problem Management,
  Quality Gate, Archive, Material Intelligence, Capability.
- No fabricated live data or fake backend connectivity implied.
