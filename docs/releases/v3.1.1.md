# TorqPro AI v3.1.1 — Release Notes

**Status:** Stable, 2026-08-30.
**Previous stable release:** `v3.1.0`
(`1041b17029601e858d1647902d395ba926e378bd`, 2026-08-29).
**Validated implementation HEAD:**
`33efc4ac8ff37f40aa8d659c4fd596d3a74c320b`

v3.1.1 is a patch release. It resolves the Tesseract OCR deployment
gap deferred from v3.1.0 and removes stale hardcoded version strings

## OCR Deployment Packaging (Faz 3.1.1A)

**Commit:** `c40efab219d7a3d705691ec8fa44b2fc4b53c9b5`
(`fix(ocr): package Tesseract languages for runtime and CI`)

### Production Docker Image (`Dockerfile`)

Added a single `RUN` layer before Python dependency installation:

```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends \
    tesseract-ocr \
    tesseract-ocr-eng \
    tesseract-ocr-tur \
    && rm -rf /var/lib/apt/lists/*
```

The `pytesseract` Python wrapper and the `backend/documents/ocr_adapter`
fail-closed logic (`is_available()` → `OCRUnavailableError` on missing
binary) were already complete and tested in v3.1.0. Only the OS-level
Tesseract binary and its English/Turkish language data were absent from
the production image. No base image, Python dependency version,
application code, or API was changed.

### CI Environment (`.github/workflows/ci.yml`)

Added a dedicated step — `Install Tesseract OCR system packages` —
immediately after `actions/setup-python` and before Python dependency
installation, installing the same three packages on `ubuntu-latest`
with `--no-install-recommends`. No existing test commands, job
structure, or error handling was changed; no `continue-on-error` or
`|| true` masking was introduced.

### v3.1.0 Known Environment Exception — Closed

v3.1.0 carried the following documented exception:

> `tests/documents/test_ocr_adapter.py::TestRealOcrExtraction::test_turkish_characters_recognized`
> requires Tesseract Turkish language data (`tur`) which is not present
> in the CI/sandbox environment. The test is not skipped or deleted.
> Docker/Tesseract packaging improvement is a separate infrastructure
> slice deferred from this release.

This exception is **closed** in v3.1.1. The test passes in both the
production Docker image and CI without modification to test logic.

## Version-Centralization Test Maintenance (Faz 3.1.1B)

**Commit:** `33efc4ac8ff37f40aa8d659c4fd596d3a74c320b`
(`test(version): derive centralization checks from VERSION`)

### `tests/test_version_centralization.py`

- Removed four stale hardcoded `"3.0.0"` assertions that had become
  false after the v3.1.0 version bump.
- Renamed `test_version_file_exists_and_is_2_9_2` to
  `test_version_file_exists_and_is_valid_semver` — the old name
  referenced a version from a prior development cycle.
- All version checks now read the authoritative root `VERSION` file
  and compare live backend/API/app state against it.
- Added SemVer format validation (MAJOR.MINOR.PATCH with optional
  pre-release/build suffix) using a compiled regex — no new runtime
  dependency introduced.
- No test deleted. No `skip`, `xfail`, or loose assertion added.
- No application code, backend, API, or frontend changed.
